# WorkBuddy 竞品差距分析与取舍建议

> 目的：客观评估与 WorkBuddy 的产品差距，区分「值得补齐的功能」与「不应跟随的广度」，为 Cyber Bear 下一阶段的产品决策提供依据。
> 范围：能力面、信任面、取舍优先级。

---

## 1. 竞品能力全景

WorkBuddy 是腾讯出品的全场景 AI 办公工作台，产品形态为桌面应用 + 云端服务，当前版本 5.3.x。其能力覆盖可归纳为七个域：

| 能力域 | 代表功能 | 依赖基础 |
|---|---|---|
| 对话与任务执行 | 问答/规划/创作/专家四种工作模式；子任务与多 Agent 协作 | 自有 Agent 内核 + 云端模型服务 |
| 办公交付 | 报告/PPT/表格/Word 生成；本地 Office 实时编辑；PDF 处理 | 腾讯文档生态 + 本地编辑引擎 |
| 记忆与身份 | 云端画像 + 本地记忆文件；角色身份文件 | 云账号体系 |
| 专家与技能市场 | 数十位领域专家、技能包、市场分发与更新 | 云端市场服务 |
| 多端通道 | 微信/企微/QQ/飞书/钉钉/Slack 等十余种 IM 通道接入 | 腾讯 IM 生态 |
| 自动化 | 定时任务（重复规则）、结果推送（微信/企微） | 云端调度 + IM 通道 |
| 连接器 | 第三方服务 OAuth 接入、自定义 MCP 服务 | 自有连接器市场 |

从数量看，Cyber Bear 目前明显少于对方。但差距需要拆开看性质：**多数功能由生态绑定支撑，与产品设计深度无关**。

## 2. 差距性质分类

### 2.1 生态型差距（不应跟随）

以下能力高度依赖腾讯自家生态与账号体系，Cyber Bear 没有对应基础，且与「陪伴优先」的产品心智相冲突：

- IM 多端通道（微信/企微/QQ/公众号/客服等）
- 腾讯文档/网盘/表格的云端读写
- 支付能力
- 微信聊天记录相关能力
- IOA 企业安全网络接入

结论：这些是对方「为什么敢做这个产品」的生态壁垒，不是可迁移的功能设计。**明确划出边界，不纳入规划。**

### 2.2 核心闭环差距（值得补齐）

自然语言 → 后台执行 → 产物交付的完整闭环，对方已有成熟形态，Cyber Bear 目前仅覆盖单场景演示。差距集中在三处：

1. **工作模式分层**：对方提供「只读问答 / 先规划后执行 / 完整创作 / 绑定专家」的渐进披露，用户可以在不打扰的模式下闲聊，需要动手时再切换。
2. **执行过程可见性**：任务进行中呈现规划、工具调用阶段、排队状态；权限请求在对话流中内联处理。
3. **产物统一出口**：所有交付物（文档/网页/图表）经统一协议呈现——HTML 自动开实时预览，文件以产物卡片展示，可一键打开；最终答复强制回显关键结果与结论，不把用户丢在折叠的工具过程里。

### 2.3 记忆与身份差距（方向相反，Cyber Bear 设计领先）

对方记忆分三层：云端画像（服务端隐式学习）、用户级记忆文件、项目级工作日志与笔记。

- 云端画像对用户不可见、无确认环节，写入信号是版本号前进。
- 本地文件层用户可读可编辑，但写入无审核。

Cyber Bear 的四层 Canon（角色自我 / 共同经历 / 场景状态 / 现实事实）在设计上即要求：**用户可见、可编辑、写入需批准**。方向上正好补对方黑盒记忆的短板，差距在执行层尚未落地。

### 2.4 自动化差距（可借鉴，但必须改权限模型）

对方定时自动化成熟：重复规则调度、运行记录、结果推送到 IM。但其后台自动化默认最高权限且关闭沙箱，属于明显的信任缺口。Cyber Bear 若做自动化，应采用同一套调度与投递模型，但**默认受限、每次运行可见、可随时中止**。

## 3. 对方的信任短板 —— Cyber Bear 的机会

| 维度 | 对方现状 | Cyber Bear 承诺 |
|---|---|---|
| 更新安全 | 桌面端更新包未做字节级完整性校验 | 发布物锁定校验和 + 签名，从第一天做起 |
| 自动化权限 | 后台任务默认最高权限、关闭沙箱 | 自动化默认受限、逐次可批准、可中止 |
| 插件执行 | 插件启动钩子直接执行脚本，无隔离 | 钩子全部纳入执行信封与审计 |
| 审计粒度 | 仅工具级记录，无文件级操作明细 | 每次文件操作可审计、可回滚、可拒绝 |
| 记忆透明度 | 云端记忆黑盒隐式学习，无确认环节 | 记忆全部用户可见、可编辑、写入需批准 |

这五条直接构成 Cyber Bear 的产品边界叙事：**功能可以比它少，信任不能比它薄。**

## 4. 取舍清单

### P0 —— 做深，不追赶数量

1. **任务闭环协议化**
   - 工作模式分层：陪伴聊天 / 需要动手时切到工作视图（对应对方的问答/规划/创作渐进披露）
   - 执行过程可见：规划、工具阶段、排队状态、权限请求内联处理
   - 产物统一出口：所有交付物经同一呈现协议（HTML 实时预览 + 产物卡片 + 一键打开），最终答复强制回显结论
2. **四层记忆落地**
   - 文件形态：角色自我 / 共同经历 / 场景 / 现实事实分层存储
   - 写入批准 + 用户可编辑 + 删除可见

### P1 —— 借鉴，带改造

3. **定时自动化**：沿用调度与投递队列模型（重复规则 + 运行记录 + 结果推送），权限默认受限
4. **专家/技能包**：采用「定义即文件」的轻量格式 + 市场分发雏形；钩子必须进执行信封

### P2 —— 先不做，等生态或验证

5. 连接器 OAuth（其凭据加密存储方案可借鉴进我们的凭据设计）
6. 本地文档实时编辑、多模态生成

### 不做 —— 明确划出边界

7. IM 通道、腾讯文档云、支付、网盘 —— 依赖对方生态，且与「陪伴优先」心智冲突

## 5. 结论

功能数量差距大，但差的是**广度**（生态绑定），不是**深度**（信任与体验）。核心闭环 Cyber Bear 的演示已通，实际差距在「模式分层 + 执行可见性 + 产物出口」三件事的协议化落地，属可执行工作量，非架构级缺口。

对齐动作：按 P0 两项拆解任务，P1 两项在核心闭环稳定后再启动；同时把第五节信任承诺写入产品边界文档，作为长期差异化的固定叙事。
