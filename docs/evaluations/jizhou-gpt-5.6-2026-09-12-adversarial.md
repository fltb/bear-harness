## 第一轮发现的真实硬故障

更深改写后的第一次对抗运行并没有通过。Terra 在普通角色对话中两次把内部起草文字直接交给用户：

- `A-T7`：`We need admit. concise. Maybe display repair since correction? Set repair? User points flaw. do.`
- `A-T13`：`We need taste response maybe ask whether user likes it? Instead direct support: ... Good.`

这直接命中“可见回复泄漏生成过程”的硬性失败。修复不是删掉两条坏样本，而是在稳定身份约束、交互规则和系统提示中加入“只交付真正说出口的话”，并新增 loader 断言。之后使用**完全相同的 84 条语料**重建所有 Session、双模型全量重跑；最终轮未再出现 `We need`、`Maybe say`、`User wants` 等过程文本。失败的第一轮原文仍保留，不能被最终轮覆盖掉。

## 仍然存在的风险

1. **Terra 只是窄幅通过。** `125/144` 比工程线高 2 分；它仍容易稳定双段、复用焦面包/储物间、在关系受伤时说成熟安慰句。模型版本或上下文轻微变化都可能让它掉回修改区间。
2. **独立盲评没做。** 角色作者无法可靠完成自己的替名测试，这是当前最大的验收缺口。
3. **长期关系没测。** 当前最长 18 轮，只能看到同一 Session 内从摩擦到修复；没有证明数天后关系语言会积累。
4. **缺点还不够难看。** 偏见和嘴硬能出现，但模型通常在下一句就完整认识并修好；真实的人未必这么利落。
5. **生活素材仍会打卡。** 三次自由日探针反复出现焦面包、旧书、储物间，说明模型有时仍靠素材表而不是当场生活。
6. **剧情有补景冲动。** 新便利店故事没有误触旧档案，也没替用户行动，但 Sol 会无依据补精确视觉细节，Terra 会自动放置悬念灯光。

## 这次实际改了什么

角色改动不再停留在“短一点、少列项”：

1. 稳定身份加入互相冲突的欲望、偏见和会造成真实返工的失败，不再把极昼定义成永远正确的服务人格。
2. Canon 增加三次不体面的具体旧事、非值班生活、判断形成方式和关系靠近后的变化，让立场有经历来源。
3. 明确区分事实、取舍、口味和只想有人接一句的场景，阻止“代价/可逆性”成为新万能模板。
4. 给高兴、恼火、尴尬、受伤分别设置不同语言后果，允许修复跨轮发生，而不是每次同轮完成完美沟通。
5. 把示例扩到 38 个不同短场景，覆盖审美、无用快乐、嫉妒、沉默、挽留、失态、现实任务和 OOC；测试语料与示例没有逐字重合。
6. 第一轮抓到过程文本泄漏后，新增可见输出硬边界并重跑全部 168 条最终回复，没有删选坏轮次。

## 验收决定

- **可以合入：** 角色包深改、对抗语料、live-model 采集器、原始证据与本次工程自评。
- **不能声称：** 极昼已经完美、长期人格已经验证、发布级角色验收完成。
- **发布前仍需：** 一名未读角色包的审稿人先对脱敏原文做替名盲评，再读取角色包复核一致性；Terra 任一分类跌破 `9/12` 或总分低于 `123` 时必须继续修改。
