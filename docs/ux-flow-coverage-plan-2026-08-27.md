# UX 全流程覆盖方案

日期：2026-08-27
目标：从“功能可用、正常态一致”推进到“用户从进入、完成任务、遇错、恢复、退出都能理解下一步”。

## 验收模型

每条关键旅程必须同时拥有四类证据，缺一项不能标记为 UX covered：

1. **交互证据**：用户通过真实可见控件完成，不用 RPC 或测试后门代替点击。
2. **视觉证据**：mobile 390×844、window 1280×800、fullscreen 1920×1080 至少覆盖关键稳定帧；异常态至少覆盖最拥挤的窗口模板。
3. **恢复证据**：刷新、Host 重启或操作失败后，用户输入、进度和可重试入口符合该流程的恢复承诺。
4. **TRACE 证据**：能用同一 trace 串起用户动作、Host 规则、模型/工具或外部任务，并确认没有凭据和真实路径泄漏。

自动断言只证明状态正确；截图只证明一个静态帧。二者必须结合，不能互相替代。

## P0：Release Candidate 前必须补齐

### 1. 首次启动到第一次有效回复

状态链：

`无 Provider → 选择接入方式 → 登录/API key → 模型同步 → 选择回复模型 → 记忆方式 → 角色 onboarding → 首次对话`

需要补齐：

- OAuth/device-code 的取消、过期、手机完成后桌面自动继续。
- API key 错误、服务不可达、模型列表为空、保存成功但模型同步失败。
- 中途关闭窗口后，从准确步骤继续；不重复要求已经完成的登录。
- 自定义 Provider 的字段级校验和“测试连接”反馈，不能等到第一次聊天才发现不可用。
- 390/1280/1920 下键盘不遮挡主操作，错误信息不会把下一步挤出视口。

### 2. 离线向量模型完整生命周期

状态链：

`未启用 → 选择离线 → 选择模型/来源 → 下载 → 校验 → 启用 → 首次索引 → 可用`

需要补齐：

- 真下载进度、速度/剩余量或至少阶段文案、取消、重试、断点或明确重新下载语义。
- 磁盘不足、校验失败、网络断开、镜像不可用、自定义路径无权限。
- 下载完成后不能仍显示“下载”；重启后不得丢失已完成状态。
- 切回在线 API 时说明本地模型是否保留以及占用空间，但不擅自删除。
- 首次索引与“模型已下载”分开显示，避免用户误以为下载完成即全部完成。

### 3. 工作代理权限与结果闭环

状态链：

`发现候选 → 核验/同意 → 用户明确委托 → 排队/运行 → 权限请求 → 允许或拒绝 → 完成/失败 → 浏览/下载结果`

需要补齐：

- 真实 Codex 的权限请求、拒绝、允许一次、允许本次会话、允许命令模式的本地截图。
- 运行取消、Host 重启后的 interrupted 状态、继续运行、继续失败。
- 多个并行 run、长指令、长路径、很多生成文件时 Header popover 与双列工作面板的压力布局。
- 失败结果必须说明“任务未完成”，不能复用 started/success 文案。
- 空输出、未知二进制、嵌套目录、同名输出和下载失败的结果体验。

### 4. 错误与恢复总旅程

需要建立统一的 UX 词汇和动作顺序：

`发生了什么 → 哪些内容已保存 → 用户现在能做什么 → 重试是否安全 → 去哪里看详情`

必须覆盖：

- Provider 超时/限流/凭据失效；草稿保留并可显式重试。
- 流式回答中断、用户停止、Host 断线、事件订阅重连。
- 陈旧 revision 冲突：不要显示原始内部错误；刷新投影后保留用户未提交编辑。
- 附件上传失败/取消/重试，目录中单文件读取失败。
- 角色包保存冲突、YAML 错误、插件 hash 改变后信任撤销。

## P1：真实产品体验完整性

### 5. 记忆的信任流程

- 候选出现原因、编辑文本、选择 scope、批准、拒绝、撤销/忘记。
- “直接记住”和“候选待批准”在文案和视觉上不得混用。
- 搜索为空、很多结果、长文本、重复记忆、关系记忆关闭后的影响。
- 删除/排除后立即消失，重启后保持；错误时恢复 canonical 状态。

### 6. 对话与信息密度压力

- 100+ 对话、长标题、中文/英文/emoji 混排、搜索与归档恢复。
- 200+ 消息、超长用户输入、代码块、表格、引用、连续工具卡、多个图片。
- composer 多附件换行、上传队列、窗口高度很小、输入法组合态。
- 双列布局在任务、权限、结果同时出现时的主次关系和滚动归属。

### 7. 角色管理与高级编辑

- 导入成功、格式错误、资源缺失、重复 ID、只读包、切换时未保存确认。
- 插件 hash 审阅、启用、包变更后自动撤销、拒绝后仍可安全使用无插件部分。
- Prompt/存储编辑的保存、放弃、冲突和重启恢复。
- Canon 添加、搜索、选择引用、编辑、删除、空状态和大型来源。
- 高级编辑必须明确是“角色包开发”，不能和普通角色设置混在一起。

### 8. 国际化与可访问性

- zh-CN、zh-TW、en 三语言分别跑 mobile/window/fullscreen 截图。
- 键盘完成 onboarding、设置、对话、权限处理、结果浏览；验证 Tab 顺序、Escape、焦点返回。
- screen-reader live region：流式结束、上传进度、下载完成、错误、权限请求。
- 200% 缩放、减少动态效果、高对比度、系统大字号。
- 不只检查 `aria` 存在，还检查 accessible name 是否能让用户区分多个相似按钮。

## P2：平台与发行体验

- Windows/Linux 字体、滚动条、原生文件选择器、路径长度和安装目录权限。
- macOS/Windows 自动更新：发现、下载、重启安装、失败、回滚或明确恢复方式。
- 首次启动冷启动耗时、离线启动、系统代理变化、睡眠唤醒与网络切换。
- packaged app 的登录回调、设备码链接、Codex 发现和 helper 校验。

## 执行顺序

1. 先定义统一错误/恢复组件和状态文案，否则每个流程会各自发明一套错误 UX。
2. 补首次启动、离线模型、工作代理三个 P0 状态图与交互原型。
3. 用规则 Provider/可控下载器/ACP fixture 自动制造每个稳定状态，建立截图基线。
4. 再用真实 Codex 和真实下载做人工验证，只验证外部集成，不让不可重复网络结果替代门禁。
5. 最后补压力、可访问性、多语言和 packaged platform matrix。

## 当前判断

现状已达到“主功能与数据恢复可进入 release candidate”的门槛，但 UX coverage 尚未完整。最优先的缺口不是再调整正常态颜色，而是让首次接入、离线下载、权限拒绝、任务失败和重启后的用户始终知道：发生了什么、什么已保存、下一步是什么。
