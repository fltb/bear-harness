实际入口仍为「角色库」与角色设置内的「编辑角色」。编辑不切换原会话，不中止后台回复，保存草稿不提前改动已安装角色。没有恢复 Canon manifest、实体表或路由树。

## 模块与所有权

- UI 分离为 `SchemaFields`、`PackageForms`、`DraftPreview`、`StudioReview`、`StudioTrial` 和草稿 `workflow`；主页面负责入口与操作编排。主聊天和试聊复用纯粹的原生工具结果解析。
- Host 的草稿文件、引用重写、状态迁移与试聊分别由独立模块负责。RPC 不接受 Renderer 指定的权威文件系统路径。
- 正式安装包仍在 `characters/<id>/`；草稿在 `companions/<id>/drafts/`；迁移备份在 `companions/<id>/package-migrations/`。
- 试聊的包快照、真实 Pi Session、数据库、状态与 Canon 索引独立放在草稿 `trials/<uuid>/`。它复用系统 Provider 与 embedding 服务，不复制凭据或模型下载；正式 Explicit/TDAI Memory 不进入试聊。
- 试聊只提供 `role_skill`、`host_state`、`host_canon`、`host_media`、`host_choices`，插件、外部执行器、正式记忆工具不加载。原生 Pi 快照与临时事件是唯一会话来源，没有轮询、第二份持久消息或执行状态机。
- 关闭先释放 Pi/索引/数据库；失败保留可见错误。Host 重启清理遗留试聊目录。删除草稿/角色时排除新试聊，等待对应资源关闭。
- 状态迁移使用持久事务日志，重启根据实际安装包 hash 完成迁移或恢复原值。仅目标角色空闲时可应用；其他角色继续运行。
- 静态/试聊素材读取校验草稿中的预期 hash，另一窗口替换文件时报告冲突，避免混用不同修订的字节。

## 明确边界与剩余发布工作

1. 静态预览用于核对素材、文案和首次见面流程，不是完整聊天布局/配色的逐像素模拟；真实模型行为用试聊核对。插件代码仍通过源码编辑，试聊不执行插件。
2. 文件移动不解析插件 JS/TS 导入，也不猜测修改自然语言引用；UI 已明确提示作者自行修改代码导入。Markdown 自动更新范围是内联链接。多窗口使用版本检查防止覆盖，不提供多 Host 共同写同一 dataRoot 的协作编辑。
3. 状态迁移按顶层字段保留或恢复默认值，不承诺猜测性地重构嵌套业务状态。旧值备份可审计；没有自动把旧语义转换为新语义的脚本生成器。
4. Electron 已更新到 43.7.7、DOMPurify 到 3.4.16，并更新可独立修复的传递依赖。剩余 `@earendil-works/pi-coding-agent@0.85.1` 内的 `undici@8.9.0` / `brace-expansion@5.0.9` 被上游 npm-shrinkwrap 固定。无效的 overrides 已删除；没有篡改 node_modules 或绕过 audit。解决需要升级/替换 Pi 依赖并完成其回归，不能用本轮 Studio 测试替代。
5. 本轮未改写角色身份、提示词、Canon 或 Skill 正文；既有角色质量发布结论不变。未完成所有主模型的正式角色质量验收、同一干净提交的平台新包与 packaged smoke，未建立新的发布证明。
6. 独立 Android runtime、APK、真机软键盘/旋转/系统返回键仍属于 Android 阶段。本轮完成的是 Studio 与响应式编辑，不宣称已完成手机独立运行。
