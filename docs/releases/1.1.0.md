# Bear Harness 1.1.0

Explicit conversation routing, Run-owned results, and configurable ACP workers.

- Keep Pi authoritative for conversation content and execution. Window selection stays local to each renderer; the Host registry manages real session resources without a global active conversation.
- Route concurrent sessions and background Run results by explicit conversation ID. Background snapshot refreshes preserve the window's latest conversation selection.
- Capture generated files as character-isolated Artifacts with ownership and integrity checks, safe previews, provenance, and native Save As or Web download.
- Use the built-in Pi worker when no runner is specified. Discover runner descriptions through `host_runners` and explicitly select Codex or a configured custom stdio ACP worker through `host_delegate`.
- Share ACP execution, permission handling, filesystem/terminal callbacks, and native session recovery across worker types. Invalid or failed selections report errors without switching runners.
- Keep Codex registration stable across CLI upgrades. New Runs discover the installed executable and record its actual version and hash; existing Runs retain their original recovery snapshot.

Recovery requires protocol support and a confirmed release of the old controller. A Codex Run whose original executable has been removed or changed remains unresolved instead of silently restarting on another version. Model execution also depends on the worker's configured provider and authentication.

These notes describe the changes; release publication uses the repository's same-commit CI package verification and checksum-signing workflow.
