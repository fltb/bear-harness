# Bear Harness 1.0.1

Bugfix release for provider settings, character setup, and response correction.

- Keep provider creation accessible after deleting the last provider, and preserve completed system and character onboarding when a model becomes unavailable.
- Remove stale configured routes when deleting a provider so adding it again makes its models selectable. Refresh Pi's shared model runtime so existing conversations can use the updated provider configuration.
- Let a new character open System Settings when no configured models are available.
- Correct assistant replies that follow skill calls, state updates, or other native tool results by locating the original user prompt on the reply's Pi branch, preserving text and image attachments.

Onboarding completion remains system- or character-owned; Pi remains authoritative for conversation branches and execution. This release does not change character prompts or memory policy.
