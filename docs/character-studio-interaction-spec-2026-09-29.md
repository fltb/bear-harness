# Character Studio 完整交互规格

> 格式校正：本稿涉及角色包字段、命名和必需文件的描述存在偏差，不可作为格式实现依据。以当前源码及 [格式校正记录](character-studio-format-correction-2026-09-29.md) 为准；此前原型通过的流程检查不证明包格式正确。

日期：2026-09-29。状态：交互设计与隔离原型，非产品实现验收。

2026-10-01：已落地首批真实编辑流程，具体功能、测试与未完成项见 [实现记录](character-studio-implementation-2026-10-01.md)。下文是完整目标，不代表全部已经实现。

本文细化并修订 `modular-android-character-studio-proposal-2026-09-24.md` 的 Studio 部分。实现以本文件的交互定义为准，Pi / Bear 的所有权继续遵循 AGENTS.md。

## 1. 已作出的设计决定

- 产品名称使用「角色库」「编辑角色」，不向普通用户展示 Hub / Studio 术语。
- 编辑器是同一应用窗口中的完整页面，占用聊天侧边栏、对话与立绘的区域；不再塞进角色设置抽屉。
- 默认两栏：内容导航 + 一个主要编辑区。预览按需打开，不常驻第三栏。
- 作者可只使用表单完成普通角色创作；高级原文和文件入口覆盖整个包，不出现“此字段保存后被表单删掉”。
- 草稿自动保存与「应用到角色」是两个明确动作。保存草稿不会改变正在使用的角色。
- 只有「应用到角色」为编辑页主按钮。校验由它自动执行；用户不需要记住先验证再应用的顺序。
- 不使用按步骤强制推进的向导编辑已有角色。新建只收名称/标识，随后进入同一完整编辑器。
- 「静态预览」和「试聊」明确区分；静态预览不伪装模型效果。
- 错误必须附着于具体字段/文件，允许直接定位。toast 只用于成功反馈，不能承载阻塞性错误。
- UI 导航、预览和作者草稿都不成为 Pi 会话、运行状态、用户记忆的另一份权威。

## 2. 入口、返回和页面所有权

### 2.1 接入现有 UI

| 现有位置 | 改动 | 操作结果 |
| --- | --- | --- |
| Sidebar 底部「角色设置」 | 改为「角色库」 | 打开角色库整页，记住原对话位置 |
| 当前角色头像/名称 | 增加带可见标签的菜单 | 切换角色 / 当前角色设置 / 编辑角色包 |
| 当前角色设置抽屉 | 保留模型默认值、记忆同意与用户数据查看 | 不再编辑人设和角色包文件 |
| 角色库卡片 | 主操作「开始对话」，次操作「编辑」 | 浏览和编辑不自动切换聊天角色 |
| 角色库工具栏 | 新建、导入、搜索 | 不依赖当前有可用模型或聊天 Session |
| Studio | 自己的内容导航、工具栏和保存状态 | app-level client、subscriptions、query cache 继续存活 |

角色库的插件信任、角色包删除和运行数据删除仍是不同操作。复制为新角色不复制会话、记忆、授权信任或 onboarding 完成标记。

### 2.2 返回规则

- 从角色库进入：返回原角色库，保留搜索、筛选和列表位置。
- 从当前角色菜单直接进入：返回原角色与会话，保留输入草稿、阅读锚点；以 Pi 最新快照显示回复。
- 返回只刷新已变化的包摘要，不重新初始化系统 onboarding 或角色 onboarding。
- 草稿已保存：直接返回，不反复要求确认。
- 草稿待保存：先完成有界 flush；成功后返回，失败才显示离开确认。
- 草稿保存失败：提供「留在这里」「重试保存并返回」「放弃未保存修改并返回」。危险操作写明丢弃的是最近未落盘修改。
- 切换章节、表单/原文、打开预览不丢弃输入、不触发应用、不关闭 Pi handle。
- 离开聊天展示页时关闭正在播放的媒体 viewer，保留会话的结果选择；真正切换 conversation 时清理旧会话的 viewer/result 本地选择。
- 另一个角色删除当前编辑目标时：转为「源角色已删除，草稿已保留」，可另存为新角色；不静默切到别的包。

## 3. 布局、滚动与视觉

### 桌面 / 平板横屏

- 顶部工具栏：返回、角色名、保存状态；右侧撤销、重做、预览、更多、应用到角色。
- 左导航约 190–216 px，按「角色 / 呈现 / 内容 / 高级」分组；页面不足高度时导航自身可滚动。
- 编辑区占剩余宽度，文本表单最大约 760 px；长正文/源码允许更宽，不拉成整屏超长行。
- 内容页是主要滚动区域。正式应用顶部工具栏固定在 app shell 内，焦点滚入时避开工具栏。
- 预览、修改摘要和文件选择是暂时的工作层；复杂内容允许扩展为全窗口子页。关闭后回到原编辑位置。
- 不在同一列嵌套多层滚动卡片。长列表分页/虚拟化，正文编辑器可以有自己的文本滚动。
- 使用现有语义色、按钮、TextField、Dialog、字体与聚焦样式。编辑面使用稳定高对比背景，不把大立绘和高噪声背景铺在长文本下面。

### 手机，≤767 px

- 第一行：返回、角色名、草稿状态。第二行：预览、更多、应用。
- 撤销/重做移入更多，保留编辑器原生文本撤销；不可删掉移动端的恢复入口。
- 内容导航为一个清楚命名的章节选择器/目录页，不做横向滚动的十二个标签。
- 编辑、预览、问题、素材选择均为单栏全屏子页；返回键先退当前层，再退出 Studio。
- 文本输入至少 16 px，主要触控目标至少 44×44 px；不能只在 hover 出现删除和排序。
- 所有排序同时提供上移/下移，不强制长按拖拽。
- 软键盘出现时当前字段/光标可见；应用按钮不悬浮遮住输入；使用真实 Android insets 和 visual viewport 验证。
- 多行字段在内容较长时提供「展开编辑」，保留草稿同步，不重复维护一份文本。
- 在 320 / 390 / 768 / 1024 / 1440 px 和 200% 文本放大下无页面横向溢出、遮挡或操作丢失。

## 4. 信息架构与字段覆盖

所有条目创建后直接进入编辑，焦点落到第一个必填字段；空值允许留在草稿中。选填字段明确标记，必填缺失不通过应用。复杂字段没有专用表单时，提供定位到对应节点的高级编辑，不吞字段。

| 页面 | 常规表单内容 | 列表操作 / 高级内容 |
| --- | --- | --- |
| 基础信息 | 名称、简介、语言、开场白、输入提示 | 新建包 id；原地编辑不可改 id；修正反馈文案、theme、work presentation 在高级分组 |
| 身份与边界 | identity.summary、invariants、knowledge_boundaries | 列表逐条编辑/增删/上下移动；人物身份唯一来源 |
| 对话方式 | interaction、agency.never、when_uncertain、成对 examples | 示例增删、复制、上下移动；system_prompt 独立折叠分组，不覆盖 behavior |
| 首次见面 | 全局步骤文案，步骤类型、标题、正文、引用/提示、按钮 | acknowledge/text/choice 三种；text 长度与 nickname effect；choice 选项增删排序；步骤预览 |
| 场景与表情 | avatar、scenes、expressions、默认项 | 名称/id、description/use_when、素材；设置默认、复制、排序、删除 |
| 媒体 | image/animation/audio/video、名称/id、asset、description/use_when | poster、WebVTT captions、loop；替换文件、预览、来源/许可关联文件 |
| 角色状态 | 顶层字段 key、类型、x-scope、title、description、default | 嵌套 JSON Schema、范围/枚举；子级继承 scope，不提供 scope override |
| 故事 | STORY.md | Markdown 编辑/安全预览；相关文本在文件树 |
| 知识 | 文档列表、标题、正文、新建/导入/删除；人物与专题的可视化编辑 | 文档标识、存放路径和引用由系统维护；不要求作者编辑 manifest；不编辑运行时用户知识表 |
| 技能 | 名称、描述、触发包含/排除、allowed-tools、priority、正文 | requires/active-when/resources/completion 的现有契约；资源文件；当前平台不可用提示 |
| 插件 | 源文件和包内资源 | 源码编辑、文件增删、依赖/信任变化说明；不在编辑器执行 |
| 全部文件 | 全包文件树和文件编辑/预览 | 新建文件/文件夹、重命名、移动、删除、上传/替换；许可证与资源元数据文件 |

禁止重新引入 roleplay wrapper、choice_sets、旧 prompt 对象、条件化媒体权限或展示历史。choices 仍是当前回复的临时工具结果，不在作者页面设计“按钮命令配置”。

编辑器必须覆盖合法 Schema 的全部字段，但不能因为原文允许编辑，就把所有普通用户必需的创作操作推给 YAML。表单覆盖验收对照实际 schema，不按截图里出现了几个输入框判断。

### 4.1 表单与原文的一致性

- 一个 draft revision 对应唯一文件集合。表单修改 YAML AST 的特定路径，未改动字段/顺序/注释尽量保持。
- 同一个文件不维护“表单草稿”和“源码草稿”两个可同时写入的版本。
- 原文语法错误：原文保留并可自动保存；显示具体文件/行/列；表单暂停并提供「修复原文」，不回填最后合法值。
- 原文语法合法但不符合 schema：仍可编辑；字段表单逐项标错，无法投影的节点保留在原文。
- 未来不支持的 format_version 以明确的只读/升级提示处理；不把未知内容重写成当前格式。
- IME composition 期间不重排内容/序列化回输入框；compositionend 后再校验与保存。
- 表单章节切换保留字段、光标和滚动；原文定位可从问题行直接跳入。

### 4.2 知识页：操作文档，不操作清单

- 默认展示文档标题和正文摘要，提供「新建文档」「导入文档」。点击标题进入大面积正文编辑；手机占满内容区域。
- 新建只填写标题、正文。系统生成稳定文档标识、包内路径和目录记录，一次草稿事务提交；空标题提示补充，空正文可保留为草稿。
- 首版导入 Markdown / 纯文本，自动加入知识资料；同名导入保留为独立文档，绝不覆盖已有内容。原型支持多选和每文件 3 MB 限制，真实限制仍按产品导入合同确定。不承诺尚未实现的 PDF/OCR。
- 改标题保留稳定文档标识，已有引用继续有效；正文编辑自动保存草稿。作者不需要填 id、路径或第二次登记。
- 删除先显示受影响的专题名称，确认后一并移除文档与结构化引用；作为一个操作撤销。正文里的自由文字不做猜测性替换。
- 已有包的文档直接出现在列表里。人物、地点、专题和文档关联仍需可视化表单；保留已有数据，不能借简化入口删掉这些内容。原型此次完成文档流程，专题/实体完整表单仍属于正式实现范围。
- 正常创作流程没有「编辑知识目录」或 manifest 表单。当前 Host 的 `canon/manifest.yaml` 是包格式中的内部元数据，Studio 自动维护；高级「全部文件」仍允许专业作者检查原始包。此次修正不删除生产 loader 的现有契约。
- 损坏资料显示可操作错误并保留原内容，不能自动用空目录覆盖。应用前的普通标题错误回到文档页，不跳到 YAML。
- 文档保存、包应用和运行时检索生效分别报告。仅保存草稿不能宣称「已索引」或「角色已学会」。

## 5. 顶部、底部与更多菜单的操作合同

| 控件 | 可用条件 | 结果 | 错误恢复 |
| --- | --- | --- | --- |
| 返回 | 页面不是正在做不可取消的提交收尾 | 按原入口返回 | 未保存失败才确认 |
| 保存状态 | 始终可见，不可伪报成功 | 待保存 / 保存中 / 已保存草稿 / 保存失败 | 失败显示重试和持久错误条 |
| 撤销 / 重做 | 存在对应编辑操作 | 修改草稿；不回滚已应用包 | 自动保存失败同普通编辑 |
| 预览 | 草稿至少可解析 | 当前修订的静态预览 | 必需资源缺失显示对应问题 |
| 应用到角色 | 有修改或新角色；无提交中的重复操作 | flush → 校验 → 修改摘要 → 确认提交 | 校验/冲突/运行中/磁盘错误分别处理 |
| 检查整个角色包 | 草稿可读取 | 自动保存后，报告错误与警告 | 点击定位，可继续编辑 |
| 更多 → 修改记录 | 无阻塞提交 | 查看时间/修订/差异，恢复为新草稿 | 被清理版本说明不可用，不崩溃 |
| 更多 → 复制为新角色 | 可取得完整草稿 | 新 id + 新角色草稿 | 重复 id 就地修复 |
| 更多 → 导出 | 可保存草稿 | 选择导出已安装版本 / 当前有效草稿 | 格式错误阻止普通 ZIP；作者备份另标草稿 |
| 更多 → 放弃未应用修改 | 有已安装基线 | 确认后回到已安装版本，留修订快照 | 不删除角色 runtime |

不显示永远不可用且无解释的控件。暂未实现的生产功能不得以可点击无反应按钮进入成品。删除角色包、删除用户数据不放在编辑工具栏里。

应用过程中：上传可取消；应用前检查可取消；最终原子提交开始后短暂防重复并显示真实进度状态，结束后恢复操作。不可用的等待必须有超时/错误出口，不无限旋转。

## 6. 素材和文件的完整交互

### 6.1 选择与上传

1. 点字段旁「选择素材」打开限定 MIME/用途的资源选择器。
2. 展示缩略图或类型图标、文件名、大小；可搜索文件名；当前素材被明确标记。
3. 用户选择已有素材，立即更新草稿引用；未点应用前不改变当前角色。
4. 上传使用原生 picker/Web input。显示每文件进度、失败原因、重试/取消，支持其他文件继续完成。
5. 同名文件提供「替换原文件」「使用新名称」「跳过」，默认使用新名称；替换时列出所有受影响引用。
6. 上传完成不自动增加 media 记录。只有用户在媒体页选择「添加媒体」时创建语义条目。
7. audio/video 必须绑定 VTT 字幕；animation 必须有 reduced-motion poster；类型/实际 MIME 不符时就地修复。
8. UI 显示 Host 的实际文件/总包大小限制，不能宣称无上限。大文件使用分块传输，不将 base64 整包压进消息或 bootstrap。

### 6.2 改名、移动与删除

- 文件路径为相对包路径；拒绝上级目录、绝对路径、越界 symlink、保留名、冲突与非法编码。Renderer 从不提供权威磁盘路径。
- 改名/移动前显示受影响引用；Host 按解析后的结构更新 manifest/Canon/Skill 的已知引用，与文件移动作为同一 draft revision 提交。
- 不能对全部自然语言正文做盲目字符串替换。无法判定的文本引用列成需作者确认的警告。
- 删除未引用文件：进入可撤销草稿删除，不每次弹模态确认。
- 删除被引用文件：禁止留下无提示断链。用户可「取消」「选择替代素材并删除」或先进入引用处修改。
- 删除必需文件可在高级草稿中暂存，但应用必须阻止；主清单不提供普通删除按钮。
- 删除默认场景/表情时，先选择新的默认项；不能应用一个不存在的 default id。
- 替换大文件成功前保留旧字节；取消/失败不留下半份素材。历史清理不能删掉仍被任何草稿/已安装包引用的内容。

## 7. 草稿保存、冲突、应用与恢复

### 7.1 草稿生命周期

- 编辑既有包：读完整包 revision 与文件 hash，创建独立 draft；打开不会改包。
- 新建：创建合法目录结构和模板资源；先保存作者草稿，不自动完成角色 onboarding。
- 用户停止输入约 600–1000ms 自动保存；页面离开、切换目标、显式 Cmd/Ctrl+S 触发 flush。
- 草稿允许不合法内容，系统仅拒绝不安全路径/超限写入。原子写入成功前不显示“已保存”。
- 文件保存按 expectedRevision 串行提交；旧请求返回不得覆盖新文本。保存通知必须对应当前 draftId/revision。
- 断网适用于 Web 客户端与模型请求；本地平台草稿仍应保存。与 Host 的 transport 丢失时保留本地未提交编辑，明确状态。
- 自动保存失败继续允许编辑，保留最后已确认 revision 和待保存内容，提供重试与作者备份途径。
- 正式存储按角色隔离，草稿 metadata 与内容遵循角色 runtime 所有权。系统库不保存角色正文。
- 草稿缓存限制、回收/导出与删除 runtime 的影响需要产品明确展示，不以浏览器缓存代替可靠持久化。

### 7.2 应用流程

`点击应用 → flush 当前草稿 → 全包校验 → 检查基线与运行状态 → 修改摘要 → 确认应用 → 重新检查 → 原子提交 → 完成`

修改摘要至少显示目标角色、来源修订、变更文件数；按用户语义分组为人物/首次见面/呈现/状态/资料/代码。普通用户先看字段级差异，源码 diff 按需展开。

应用结果必须区分：

- 包已保存、稳定上下文将在 Session 再次打开时加载。
- 插件内容变化，新的 hash 未被信任；不会随保存自动执行。
- 新角色已安装，可从角色库开始首次见面；尚未使用用户默认模型时显示正常角色 onboarding。

正在回复：可存草稿，应用前阻止并解释原因；不自动 abort、不创建新的后台“等待应用”状态机。最后提交须与新 Session 路由建立资源排他并再次核验，避免检查后立即开始生成的竞态。

当既有 state_schema 的删除、类型/scope 变化不兼容当前 runtime 时，阻止原地应用；列出受影响字段，提供返回修改或复制为新角色。模型默认值、用户记忆和 onboarding 完成状态不随包更新重置。

### 7.3 并发冲突

- 冲突由整个包的基线发现，不仅检查 character.yaml。
- 不同文件或同一文件不重叠的结构化字段可做有证据的三方合并；合并结果仍须校验。
- 同字段/同段文本/同资产冲突展示基线、另一处修改、我的草稿；逐项选择，或打开编辑区手动合并。
- 不默选“我的版本”；取消解决冲突仍保留草稿。
- 解决后形成新草稿和基线，重新进入应用检查，不立即跳过摘要自动覆盖。
- 二进制冲突显示缩略图/尺寸/大小/hash，不展示无意义的 base64 diff。
- 删除对方修改的文件、对方删除本地修改文件、包已删除、权限变只读均有独立说明。

### 7.4 崩溃与恢复

- 启动发现草稿：角色库卡片显示「继续编辑」，含最后成功保存时间。
- 应用中断：Host 的事务恢复保证旧包或新包整体可用；UI 重新查询提交结果，不能盲目重试不幂等提交。
- 多次点击/网络超时：提交以 draftId + revision + basePackageHash / operationId 定义幂等语义，不重复安装。
- 低磁盘/文件被占用：错误条指出操作失败，草稿保留；未提交半成品不得替换运行包。

## 8. 预览、试聊与移动端兼容

静态预览：读取确定 draft revision，选择场景/表情，检查长名称、开场、媒体与 first meeting；不更改生产 Character/Display。媒体打开使用独立 viewer，支持播放、展开与关闭时停止；包媒体不进入 Run Artifact 容器。

试聊是独立工作流，不放一个返回固定句子的假聊天框：先校验 → 选择已配置模型 → 展示会产生模型请求 → 创建隔离测试角色/runtime → 用真实 Pi Session 交谈。试聊使用草稿快照；继续编辑时显示「试聊基于旧修订，重新开始以加载更新」。禁止自动带入生产角色显式/自动记忆；停止/删除试聊释放所有资源。

缺少模型时静态预览可用，试聊提供设置入口；不把整个创作页面挡在系统 onboarding 后面。真实角色质量验收继续遵循仓库 live-model rubric，预览不能证明角色对话质量。

Android 允许编辑、保存、导出包含桌面功能的完整包。兼容报告区分：

- 包格式错误：任何设备都不能应用。
- 本机不能执行的可选能力：保留文件，明确禁用范围；插件不能运行但可创作。
- 角色依赖关键不可用能力：指出对应 Skill/插件，不向模型注册假工具；作者选择修改或仅保存/导出。

能力说明由 Host 装配结果生成。切换为手机配置不能删除插件、偷偷删技能或改变身份提示词。

## 9. 错误文案与恢复出口

| 情况 | 界面文案示例 | 必须存在的下一步 |
| --- | --- | --- |
| 名称为空 | 请填写角色名称 | 定位名称字段 |
| YAML 错误 | character.yaml 第 N 行无法解析，原文已保留 | 打开该行；继续存草稿 |
| 素材缺失 | “窗外的山”使用的文件不存在 | 选择替代文件 / 上传 |
| 默认项被删 | 请选择一个有效的默认场景 | 场景选择 |
| 字幕缺失 | 音频需要 WebVTT 字幕 | 上传或选择字幕 |
| 保存失败 | 草稿尚未保存：存储空间不足 | 重试；留在页面；作者备份 |
| 外部冲突 | 已安装角色在另一处被修改 | 查看冲突并选择；暂不处理 |
| 正在生成 | 此角色仍在回复，可以先保存草稿 | 返回编辑；用户自行回聊天处理 |
| schema 不兼容 | 此字段已有数据，不能直接改变作用域 | 恢复原定义 / 复制为新角色 |
| 插件变化 | 插件代码已改变，需要重新确认信任 | 保存完成；从信任入口处理 |
| 导出取消 | 不显示错误 | 回到编辑器，草稿不变 |
| 目标已删除 | 源角色已删除，草稿仍在 | 另存新角色 / 导出草稿 |

不使用只写“操作失败”的 toast；Host reason 映射为具体动作与资源，敏感内部路径不直接显示。

## 10. 可访问性与性能验收

- 所有操作有可见名称；图标辅助而非唯一解释。分组和表单有 label，必填和错误有程序可读关联。
- 目录键盘可达；Dialog 焦点进入、循环、Esc 返回并恢复到触发控件；从问题跳转时聚焦具体输入。
- 输入框内 Cmd/Ctrl+Z 保留原生文本撤销；全局操作撤销只处理明确操作记录，避免争抢快捷键。
- 屏幕阅读器只播报保存状态变化/错误/操作结果，不逐字播报每次输入。
- 文本对比度 WCAG AA；高对比、暗色、减少动画、200% 字体下测试。
- 不因每次键入重建整份 UI；编辑长文和 IME 不丢光标。素材缩略图懒加载、URL 及时释放。
- 字段输入到视觉响应目标 <100ms；后台校验不阻塞输入。10MB 文本/大包需明确界限和加载过程，不一次加载全部二进制。
- 列表达到产品上限时仍可新增定位、搜索和删除；超限在动作处解释，不能只在最终提交报错。

## 12. 工程实施边界与交付顺序

建议 UI 模块：AppNavigation、CharacterLibraryPage、CharacterEditorPage、DraftSession、ManifestForms、PackageFiles、AssetPicker、ValidationIssues、ApplyReview、ConflictResolver、StaticPreview。

这些模块是职责边界，不规定都建立独立 npm package。AppNavigation 持有页面与返回目的地；DraftSession 持有作者输入与保存事务；现有 Pi 投影继续由既有 provider 管理。原型中的文件映射与模拟运行状态不能复制到生产 Host。

工程顺序：

1. 建立真实作者服务：完整包快照、逐文件操作、草稿 revision、二进制存储、校验与原子 commit。
2. 接入独立页面和返回规则，先完成 U01/U02/U03/U11，证明不丢数据。
3. 按字段覆盖矩阵接全部表单/文件/素材，不保留旧编辑器双写。
4. 完成引用、安全校验、冲突、schema 兼容、静态预览与隔离试聊。
5. 手机适配和真实 Android 系统能力测试；执行现有适用质量门槛。

## 13. 当前原型的真实性边界

原型包含 12 个内容页面、共享 YAML AST、可编辑文本/列表、真实浏览器选文件、文件增删改、引用替换、自动保存状态模拟、版本恢复、冲突选择、应用检查与确认、静态预览、桌面/手机重排。

为了在对话沙箱中可运行，数据只保存在当前预览内存，刷新重置。原型的保存、应用、冲突、正在回复与 Android 能力是交互模拟，未调用 Host / Pi。没有真实磁盘持久化、系统 ZIP 导出、原生分享或模型试聊。

原型中的高级格式使用原文入口覆盖；正式产品需要按第 4 节完成 schema 全字段表单。其轻量校验不是 Host 完整包校验，不能作为合法角色包验收器。示例人物/素材只为演示交互，不是正式角色改写，也未进行模型质量评分。

原型最终通过 38 条自动化流程检查、5 种外层宽度（320/390/768/1024/1440 px）的横向溢出检查、320/390 px 下全部 12 章节的检查。身份/基础信息/媒体/知识/文件五页在明暗主题下的 axe WCAG 2 A/AA 自动检查均无报告违规。该自动检查不等于完整无障碍认证。

新增 6 条知识文档流程检查，覆盖无配置入口、新建及整体撤销、标题/正文编辑、删除及整体撤销、多文档导入、错误定位。视觉复核查看了知识列表和手机编辑页，以及桌面、手机、暗色及手机冲突状态截图，修复了 hidden 按钮被样式误显示、移动工具栏拥挤与遗留反馈文字。新增/复制/切换角色的原型工作区相互独立。证据：[原型验证记录](evidence/character-studio-prototype-2026-09-29.json)。产品验收仍以 U01–U18 的真实实现结果为准。

发布决定：不发布。当前交付用于确认可执行的 UI 合同和原型操作，尚不具备生产可用性的结论。
