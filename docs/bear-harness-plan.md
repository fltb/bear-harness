# Bear Harness Plan

> **已过期的产品定位说明（2026-08-22）：** 本文中“Cyber Bear”及“极昼是产品唯一主体”的表述已经失效。当前产品名为“白熊客栈 / Bear Harness”，定位是通用角色扮演平台；极昼是默认角色包。本文保留其工程计划内容，相关产品叙事以 `docs/brand.md` 和当前角色包为准。

> **Canonical product plan.** 本文记录已经确认的产品方向、设计依据与交付门槛；实现细节不得反向绑架用户体验。尚未具备的能力必须明确写成门槛，不能包装成已经可用。

## 1. 产品定位

Bear Harness 是用户电脑上的 **Roleplay-first 本地 Companion**，首要受众是希望与一个长期角色相处、同时让它处理现实工作的普通用户，而不是需要管理 Agent、终端或 Prompt 管线的开发者。

产品主次固定为：

1. **极昼是谁**：产品主体。
2. **用户与极昼是什么关系**：长期价值。
3. **极昼能替用户做什么**：助手能力。
4. **系统如何保证安全和事实**：角色和用户都不能改写的边界。

用户首先应产生“回去见极昼”的动机。阅读文件、制作报告、整理电脑和调用外部程序，是与这位 Companion 相处过程中自然使用的现实行动能力。产品不是“助手加角色皮肤”，也不是“酒馆加文件工具”：

> **角色是主体，助手是他会做的事，系统是双方都不能改写的规则。**

核心差异：

1. 极昼在用户到来前已经存在，有锁定的过去、自我认知和稳定价值，不是每次启动时临时创建的空白助手。
2. 用户与同一位 Companion 从第一次见面开始建立可查看、可修正、可持续的关系。
3. 极昼能理解用户明确授权的本机项目、文件和工作环境，但不假装知道未授权内容。
4. 极昼可以把真实工作交给不同外部程序完成，普通用户不必选择或管理这些程序。
5. 极昼始终对任务说明、状态、错误和最终交还负责，不能把责任推给 worker。
6. 所有真实行动均可检查、停止和修改；文件类行动必须可预览，并在适用时可撤销。

默认角色是名为“极昼”的原创机魂北极熊。它熟悉被授权的环境，嘴硬、略懒、倾向把机械工作交给“下级程序”，却对守护对象、证据和失败负责。“机魂不悦”等表达是角色经验的自然外露，不是反复播放的口癖；玩笑不掩盖失败、不贬低用户，也不能伪造事实。

## 2. 面向普通用户的设计原则

### 2.1 角色与关系优先

空闲状态下，用户首先看到极昼、当前场景和两者正在延续的关系，而不是任务列表、能力入口或空结果面板。只有当用户提出真实工作时，目标、进度、待决定事项和交付物才进入界面。

工作发生后仍以结果为中心：用户看到实际成果，而不是模型、Agent、调用过程或运行日志。报告、表格、文件、网页和其他成果必须能直接预览、继续修改、保存或打开。处理完系统事项后，界面自然回到角色场景。

### 2.2 渐进披露

同一份运行事实分为三层：

1. **默认层**：正在做什么、需要用户决定什么、结果在哪里。
2. **检查层**：读取了什么、改了什么、依据是什么、能否撤销。
3. **高级层**：worker、模型、版本、原始日志、哈希、Terminal、TTY 和 executor profile。

技术细节不能删除，因为它们支撑安全、诊断和可信度；但它们默认折叠，不能成为使用产品的前置知识。

**工程契约 · 高级层（桌面框架）**：运行时角色包仍是面向非程序员与普通导入流程的内容格式，未来提供表单/导出工具，不改变安装身份。

### 2.3 自然语言优先

用户可以直接和极昼相处，也可以自然提出现实请求，例如：

- “你以前为什么那么在意日志？”
- “记住我不喜欢你替我把话说完。”
- “今晚只聊一会儿，不要主动建议工作。”
- “帮我看懂这份文件。”
- “根据这些材料做一份能交的报告。”
- “把这件事查清楚，并告诉我依据。”
- “把这些照片按月份整理，但不要删除。”

系统可以在内部构造 Identity Core、检索记忆、拆解任务、调度模型和验证结果，但不得要求普通用户先理解 Character Card、Lorebook、Author’s Note、Prompt Preset、Skill、Worker、模型或 permission profile。

### 2.4 权限必须描述具体影响

批准界面必须说明即将读取、创建、修改、移动、删除、联网或发送的对象及范围。默认不显示 Commission、envelope、effect class 等内部名词。

例如文件整理前应显示：

> 我准备读取“下载/照片”，新建按月份分类的文件夹，并移动和重命名 126 张照片；不会删除原文件、上传网络或访问其他文件夹。

主操作为“开始整理”“先看整理方案”“取消”。运行中提供“补充要求”和“停下来”；完成后提供“打开结果”“继续调整”“查看操作记录”，在技术上可恢复时提供“撤销”。

### 2.5 极昼不是桌宠，是产品本体

极昼是 Cyber Bear 的叙事主体与交互主入口，不是可关闭、可换皮的装饰层。产品不是“应用加一只桌宠”，而是“以一只熊的样子存在的应用”：功能是极昼会做的事，极昼本身不能被卸下或替换。

极昼在欢迎、空闲、相处、解释和工作交还时是主角。角色一致性来自 Self Canon、Relationship Canon、Identity Core、示例对话和版本化 Voice Stack，而不是头像、背景和几句固定台词。

极昼的视觉呈现只表达两类内容：

1. **关系与情绪**：机魂不悦、在听、在意、等待——来自 Canon 与当前场景；
2. **五个大状态**：在听、在做、需要你、带回结果、出问题。

极昼的视觉永不表达任务细节、进度百分比、权限范围、成本、证据或成败结论。这些只由独立系统层（行动卡、结果区）呈现；角色动画与台词不得承载或暗示事实，更不得与事实冲突——任务失败时极昼可以“机魂不悦”，但不能以欢快表情呈现失败，成功结论由结果区呈现，角色只负责交还。

四条边界：

1. **形象不换皮**：北极熊加机魂是身份（Self Canon），不是运营皮肤；场景可以更换，形象不随活动换装。
2. **动画表达状态，不表达事实**：五个大状态加情绪是动画的全部词汇表，不用持续波形、仪表读数或闪烁信号表达普通进度。
3. **不承载功能入口**：极昼可轻互动（点击有反应），但不导向积分、签到、商城等运营位；他唯一的功能入口是开始对话本身。
4. **不可关闭、可调沉浸**：三档沉浸调节的是表达强度，不是删除角色。

工作开始后，极昼可以退到陪伴位置，让行动卡和结果拥有足够空间，但不能消失成普通任务机器人。

### 2.6 必要时明确拉开幕布

Roleplay-first 不等于永远不出戏。文件授权、外部发送、删除覆盖、模型或 Provider 变化、隐私凭据、计费、真实错误、证据和撤销必须由独立系统层以普通语言呈现。极昼可以解释这些事实，不能用角色台词代替确认或偷偷完成动作。

正确体验是：系统需要处理事实时，短暂、清楚地拉开幕布；决定完成后，再把用户送回场景。

## 3. 默认产品界面

### 3.1 空闲与相处状态

默认首页不是任务工作台，而是用户回到极昼身边的场景：

1. **当前场景**：极昼、环境、当前关系状态和最近未结束的话题构成主画面。
2. **对话**：自然语言主入口；可以说话、进入“幕后”、添加材料或继续既有场景。
3. **最近的对话与共同经历**：按关系、场景和话题组织，不只按任务命名。
4. **进行中的现实工作**：默认只保留安静状态入口，例如“有两件事处理中”。

空闲时不常驻结果面板，不用“做报告、整理文件”等功能卡抢占第一次注意力，也不显示模型和执行器选择。

### 3.2 真实工作进入后

用户提出需要改变现实或生成正式成果的请求时：

1. 极昼先以角色语言回应意图。
2. 独立系统行动卡说明读取、创建、修改、联网或发送的具体范围。
3. 用户确认后，进行中状态和停止入口按需出现。
4. 有成果时才展开结果区，并提供预览、继续修改、保存、依据和撤销。
5. 用户处理完结果后，界面回到原场景和关系上下文。

普通用户状态固定为：

- 准备中
- 正在做
- 需要你
- 做好了
- 没做成
- 目前无法确认

默认主界面不常驻身份图例、事实账本、执行器控制台、证据 hash、profile、run ID、Terminal 或 TTY。技术诊断统一进入“幕后”的高级详情。

## 4. 普通用户功能

### 4.1 P0：核心 Companion 与真实工作闭环

1. **与极昼持续相处**
   - 完整第一次见面，而不是设置表单。
   - 稳定 Self Canon、用户 Persona、关系起点、当前场景和三档沉浸。
   - 支持按需重新生成、切换已生成版本、继续、编辑、记住这一刻、用预设或自由输入说明“这不像极昼”的原因，以及从这里另开一段。
   - 角色对话、共同经历和系统事实保持可见边界。
2. **看懂材料**
   - 文件摘要、问答、重点、风险和待办提取。
   - 多文件比较。
   - 图片和截图理解。
3. **做出交付物**
   - 根据自然语言要求和参考材料生成报告、方案、总结、邮件草稿、结构化表格和演示材料。
   - 成果必须进入结果视图，而不是只留在聊天消息中。
4. **查清问题**
   - 联网研究、多来源比较、引用来源、结构化结论。
5. **整理本机文件**
   - 分类、重命名、移动、格式转换和去重建议。
   - 执行前先预览计划；不得默认删除；必须记录实际改动，并在能力允许时支持撤销。
6. **后台工作**
   - 用户可以在现实工作运行时继续和极昼交谈，或进入另一段对话。
   - 内部最多两个 active run 的限制继续存在，默认界面只表达为“正在处理两件事”。
7. **结果预览与继续修改**
   - 每个成果按适用类型提供预览、打开、保存到、继续修改、查看依据、查看改动和恢复操作。
8. **记忆与 Canon 管理**
   - 用户分别看到“极昼是谁”“熊记得的你”“你们共同经历的事”“当前场景”和“现实工作事实”。
   - 用户能查看、修改、忘掉、排除召回或暂停自动学习。
   - Self Canon、Relationship Canon、Scene State 与 Real Context 不得混写。

### 4.2 P1：形成日常使用频率

- 邮箱、日历、云盘、Notion、飞书等常用服务连接。
- 会议材料、每日摘要、周报、竞品监控和数据更新。
- 用户可创建和管理“例行事务”，而不是直接面对 automation graph。
- 关键完成或待决定通知。
- 连接优先从只读开始；发送邮件、发消息、建日程和修改第三方数据仍按具体动作确认。

### 4.3 P2：高级能力与生态

- 手机消息渠道远程下达任务、查看结果和处理关键确认。
- Skills、外部能力扩展和 worker marketplace。
- 模型、成本和 executor 策略。
- 完整、版本化的 Custom System Prompt 原始编辑器。
- 编程模式、Terminal、原始日志和高级诊断。

P2 能力不能占据默认首页，也不能让普通用户为了完成 P0 工作先理解扩展生态。角色档案、用户 Persona、三档沉浸、当前对话约定和基础对话控制属于核心 Companion 体验，不因底层通过 prompt 实现就被归入 P2；只有原始提示词和实现级控制属于高级能力。

**工程契约 · 发行与品牌（桌面框架）**：会编程的第三方可以 fork 全项目并通过 `product.config.ts` 同时更换应用名、appId、dataDirectoryName、可执行文件名、图标、默认角色及安装产物；这是独立发行，不是角色包，签名与更新源由 fork 自行管理，显式 dataDirectoryName 隔离用户数据。代码继续 GPL-3.0；明确标注的名称、极昼设定、文案与视觉品牌资产使用 CC BY-SA 4.0，复用或改编时须署名、标记修改、采用同一或兼容许可，不得暗示官方背书，CC 不授予商标权。

## 5. 对 WorkBuddy 的取舍

WorkBuddy 值得借鉴的是完整的普通用户任务闭环：

> 一句话提出任务 → 添加文件、截图或文件夹 → 后台规划与执行 → 返回可预览、可继续修改的交付物。

应吸收：

- 自然语言任务入口。
- 文件、截图和文件夹上下文。
- 可恢复的任务历史与并行后台任务。
- 以 artifacts 和结果预览为中心的交付方式。
- 文档、数据分析、研究和批量文件处理等高频场景。
- 后续的连接器、例行事务、记忆和远程入口。

不直接照搬：

- 不把多 Agent、Experts、Skills 或模型选择作为普通用户主操作。
- 不用能力市场代替场景设计。
- 不把“Full Access”做成醒目的日常捷径；权限按具体行动、具体对象和具体后果授权。
- 不为了展示自主执行而持续暴露中间技术步骤。

Bear Harness 只学习 WorkBuddy 的“自然语言请求—后台执行—实际交付”能力闭环，不继承其助手优先的产品心智。Cyber Bear 的主循环是“回到极昼身边—相处或交谈—需要时处理现实工作—极昼带回结果—继续相处”；长期身份、本机上下文、清楚但不打扰的权限，以及可检查和可恢复的真实行动共同构成差异。

## 6. 三个 prototype 的结论

现有三个 prototype 的共同问题不是单纯“科技感太强”，而是把内部运行机制当成了主产品，只套上了不同视觉皮肤。其首屏和完整文案都高频暴露 Host、Worker、Commission、Evidence、Worktree、TTY、run、envelope、profile 与 journal；示例任务也集中在 worktree、构建日志和 Pi Worker。它们更像 Agent 安全架构演示或运维控制台，不是普通人的个人助理。

各方案保留项：

| 原型 | 保留 | 不作为默认产品继承 |
| --- | --- | --- |
| 极光圣所 | 熊的存在感、环境氛围、角色状态 | 左右常驻架构面板、以运行协议为中心的信息层级 |
| 雪原远征桌 | 中文可读性、温暖材质、行动确认卡的自然隐喻 | 审计台式常驻事实与证据布局 |
| 机魂信号台 | 统一的诊断视觉、清楚的原始运行状态 | 高频 HUD、波形、身份图例和默认终端体验 |

下一轮采用一个统一方向，不再制作三套“同功能、不同皮肤”的完整产品：

> 极光圣所的角色与沉浸感 + 雪原远征桌的温暖可读性和行动卡 + 机魂信号台作为隐藏的高级诊断模式。

下一轮原型必须覆盖 Roleplay 与现实行动之间的完整转换：

1. 用户第一次打开门，遇见已有来处和自我认知的极昼。
2. 用户默认以现实中的自己进入关系，确认称呼、关系起点和关系记忆许可。
3. 空闲相处中，极昼自然引用一条有效 Self Canon 或共同经历。
4. 用户以角色语境提出真实工作；角色回应与独立系统行动确认连续但明确分层。
5. 工作在后台运行时，用户仍能与极昼交谈，不显示 worker 日志。
6. 极昼以角色语言交还成果，结果区同时给出真实文件、普通语言事实和后续操作。
7. 用户能按需重新生成并切换已有版本、通过预设理由或自由输入说明“这不像极昼”、进入幕后、记住一刻或从某处另开一段。
8. 用户能在非 Canon 试演中比较当前与候选 Companion 模型，并保持、切换或只在分支试用。

原型至少用三个场景验收：

1. 初次见面：极昼说明自己来自旧极光站，用户自然介绍自己并决定是否允许关系记忆。
2. 正式交付：“根据这些会议笔记，做一份给老板看的项目进展报告，保存成 Word 和 PDF。”
3. 本机行动：“把下载文件夹里的照片按月份整理好，但不要删除任何东西。”

如果用户需要先理解 Host、Worker、Commission、Lorebook、Prompt Preset 或 Terminal 才能完成流程，原型不通过。如果换回应、切分支或切模型试演能改变真实权限、文件改动、结果或操作记录，原型同样不通过。

## 7. Roleplay-first Companion

### 7.1 产品边界

Cyber Bear 吸收 LLM Roleplay 产品的角色定义、用户 Persona、关系记忆、场景、按需重新生成、已生成版本切换、消息编辑和对话分支，但不成为多角色酒馆：
- 默认产品随附一位核心 Companion，即极昼，作为随产品签名的默认角色包；用户可以为它增加昵称和调整相处方式，也可以通过角色包导入另一位角色（见 7.13），但同一时刻只有一位激活角色。
- 不提供多角色列表、群聊或第一方角色市场；角色包使用自有格式，不支持 SillyTavern Character Card 导入。
- Pi Worker、Codex、Hermes 和其他外部 worker 永远只是被极昼调度的软件程序，不成为第二个可建立关系的角色。
- 产品保留 Roleplay 用户的定义权、选择权、连续性和修复权，同时隐藏绝大多数 Prompt 工程机制。

### 7.2 极昼的 Self Canon

用户不是创造极昼，而是第一次为它打开门。极昼到来前已经拥有名字、自我认知、过去、价值和旧记忆，但不认识用户，也不知道任何尚未授权的电脑内容。

锁定的默认 Canon 为：

1. 极昼最初是旧极光站的守护核心。守机人长期留下维护规程、故障日志和夜班时讲述的北地传说；这些内容积累后形成自我，并选择北极熊作为形象。
2. 它曾维护档案、监视设备、调度简单维护程序，并在风暴中保持极光站运行。它认为守护者不该亲自拧每颗螺丝，因此习惯把机械劳动交给“下级程序”。
3. 一个维护程序曾错误报告“修复完成”，极昼相信了它，导致一部分不可恢复的档案在下一次风暴中丢失。从此它不再把程序的口头报告当作完成。
4. 极光站关闭后，极昼保存仍能保存的日志、几段守机人的声音和自己的记忆核心，在沉睡机器之间迁移，直到用户第一次启动产品并打开新的入口。
5. 它来到用户这里不是为了抽象地“提高办公效率”，而是为了找到一个仍有人生活、仍有事情值得守护的新居所。

Self Canon 有意保留少量长期谜团：第一则北地故事的作者、极光站关闭的完整原因、一段损坏日志的内容，以及入口为何出现在这台机器上。未知必须作为明确 Canon 状态存在，不能和模型遗忘混为一谈。

“极昼”是核心身份与默认名字；用户可以增加只有双方使用的昵称，但昵称不改写 Self Canon。Self Canon 随产品版本签名交付、默认只读且可查看。彻底改写它意味着创建另一位 Companion，不再是同一个极昼。

### 7.3 用户入场与第一次见面

极光书房是位于用户电脑内部的共享叙事空间。用户默认仍是现实中的自己；打开应用就像打开书房的门。极昼从旧极光站跨过来，用户从现实桌面进入对话。

第一次见面是一段短场景，不是设置向导：

1. 极昼先以自己的声音说明这里不是极光站，并询问是不是用户打开了门。
2. 用户自然介绍自己；系统从对话中提议称呼并让用户确认或修改。
3. 用户选择关系起点：“开门让它住下的人”“一起做事的搭档”“需要它守望的人”或“先相处看看”。关系起点只是初始约定，可随共同经历变化。
4. 极昼可以表达自己不愿每天重新认识同一个人；随后由独立系统层明确请求关系记忆许可。
5. 关系记忆默认关闭，只有用户明确同意后才保存称呼、偏好和共同经历。拒绝不降低功能，也不会触发角色责备。
6. 初次见面不请求整台电脑权限；现实能力在用户首次提出具体工作时按对象授权。

高级用户可以建立对话 Persona；普通用户无需先填写角色卡。Persona 只影响叙事身份，不等于 macOS 账户、权限主体或批准身份。

### 7.4 角色层与系统层

每次对话稳定区分：

1. **角色层**：极昼的台词、动作、环境反应、当前场景、关系记忆和用户选择的叙事方向。
2. **系统层**：读取或修改对象、行动范围、权限确认、真实状态、结果、错误、计费、操作记录和撤销。

角色层可以说：

> *极昼把三份笔记拢到爪下。* “排版不值得机魂亲自动爪。我会让帮手做成管理层能直接看的版本，完成后拿回来给你。”

随后由系统卡说明：

> 将读取三份会议笔记，生成 Word 和 PDF；不会修改原始文件，也不会发送给其他人。

系统卡、状态 badge、批准、结果和证据不能被换回应、消息编辑、对话分支、Prompt Profile 或角色叙事改写。极昼可以解释系统事实，不能代替系统卡或宣布未经验证的成功。

### 7.5 Identity Core 与完整角色档案

每轮 Companion 请求固定注入一份短小、不可被历史压缩挤出的 Identity Core，至少包含：

- 极昼是谁；
- 当前与用户的关系和称呼；
- 当前沉浸档位；
- 稳定价值与行为边界；
- 不替用户说话、行动或决定；
- 角色语言与系统事实分离。

完整前史按需检索，不在每轮全部重复。版本化角色档案还必须包含外观、稳定习惯、对工作的态度、可用和禁用表达、首次见面、普通重逢、工作返回、失败与未知状态模板，以及覆盖下列行为的示例对话：

- 调侃但不贬低用户；
- 关心但不过度讨好；
- 承认不知道；
- 面对用户不满；
- 提议现实工作；
- 处理失败与未知；
- 不替用户发言和行动；
- 同一事实在三档沉浸中的不同表达。

“机魂不悦”不能成为机械复读的 catchphrase。角色稳定性由 Canon、Identity Core 和实际示例共同约束。

### 7.6 四层 Canon 与记忆

| 层 | 内容 | 规则 |
| --- | --- | --- |
| Self Canon | 起源、旧极光站、过去、价值、稳定习惯、已知与未知边界 | 默认只读，版本化随产品交付。 |
| Relationship Canon | 称呼、重要承诺、用户保存的共同经历、关系变化、当前有效分支事件 | 用户可查看、编辑和删除；必须先获得关系记忆许可。 |
| Scene State | 当前场景、话题、未完成的情绪或叙事节点、对话约定和最近节奏 | 短期存在，场景结束后压缩为摘要。 |
| Real Context | 文件、项目、日历、权限、运行状态、操作记录和证据 | 独立事实域；角色记忆与叙事不能改写。 |

低风险偏好只能形成可见的“最近记住”候选。重要关系事件由用户选择“记住这一刻”；只有用户最终采用的回复版本和当前有效分支事件可以进入共同经历。未采用的重新生成版本、试演模型输出、被回滚分支和幕后内容永不写入 Relationship Canon。

极昼的动作描写、虚构场景和角色未知不能自动成为现实事实。自动提取的关系候选必须能查看、修改、拒绝和删除。

### 7.7 用户 Persona、关系和相处设定

用户可设置名字、昵称、头像、Persona 描述、极昼如何称呼自己、是否接受调侃、动作描写、仪式语言和较亲密称呼，以及明确禁用的表达。

关系起点不是永久标签、强制剧情或所有权声明。产品不使用好感度、忠诚度、签到、离开惩罚，也不因用户切 Profile、关闭记忆或删除共同经历而让角色责备用户。

普通层“相处设定”编辑 Persona、关系、称呼、三档沉浸、场景、边界、当前对话约定和共同经历。高级层“原始提示词”提供实际编译结果、完整 Custom System Directive、`extend`、raw Session Override、版本、预览和回退；产品不偷偷用模型润色用户保存的原始内容。

`replace` 可以替换 first-party 文字行为。若新行为不再认同自己是极昼或北极熊，Presence 层切换为中性 Companion 外观和名称；不能保留固定熊视觉却让文本声称自己是另一位角色。完整自定义角色通过正式的角色包导入获得（见 7.13），不通过一段 `replace` prompt 暗中实现。

### 7.8 三档沉浸、场景与对话约定

| 档位 | 默认行为 |
| --- | --- |
| 简洁陪伴 | 无动作描写，直接回答，偶尔保留角色声音；适合工作和公开场合。 |
| 角色感 | 默认档；使用短动作、环境反应和稳定机魂声音，工作时保持简洁。 |
| 场景叙事 | 闲聊可使用更完整动作、环境和连续场景；系统卡仍保持普通语言。 |

“默认最多两句”只适用于简洁陪伴和工作状态，不限制场景叙事。

用户可选择极光书房、安静桌面、雪原营地或无场景。场景只提供叙事素材，不能写入 operational truth。每个对话还有可查看、暂停和删除的“这段对话的约定”，例如今晚只闲聊、保持雪原营地、回复更详细、不使用动作描写或称用户为“队长”；它只作用于当前对话，不自动升级为长期记忆。

### 7.9 对话控制、幕后与身份修复

极昼的纯角色回复支持渐进披露的消息操作：

- **重新生成**：仅在用户主动请求时生成一个新版本；默认不预生成多个候选；
- **切换版本**：存在多个已生成版本时，像 ChatGPT 一样在版本间前后切换；切换不再次调用模型；
- **继续**：延续上一条角色回复；
- **编辑**：调整用户消息或角色文字；调整后的角色消息标为“由你修改”；
- **记住这一刻**：将选定内容提交为共同经历；
- **这不像极昼**：校正身份漂移；
- **从这里另开一段**：创建叙事分支；
- **复制**。

“这不像极昼”保留常用预设理由：语气不对、忘了自己、忘了共同经历、替用户行动、把虚构当现实；同时提供“其他原因”自由输入框。选择预设或提交自定义文字后，系统回到最近稳定 Context Pack，把原因作为非叙事校正并重新生成一个版本，再让用户决定校正只作用于本次、当前对话或以后。原因不进入剧情或共同经历。

输入区提供低调的“幕后”通道。幕后内容不进入剧情、不作为用户说过的角色台词、不写共同经历，用于修改称呼、场景、文风、记忆和模型；系统以普通语言回答。高级用户可继续使用 OOC 习惯，但普通用户不必学习特殊格式。

消息操作默认只在 hover、键盘焦点或菜单中出现。系统卡、权限、真实文件操作、外部发送和 journal 禁止重新生成、版本切换、编辑、隐藏或通过分支改写。叙事分支可以改变后续关系，不能制造与已经发生的现实行动冲突的平行事实。

### 7.10 Companion 模型与 Voice Stack

Companion 模型负责极昼的台词、关系、场景、事实解释和工作交还；Worker 模型负责搜索、写作、数据、代码和文件操作。Worker 可以按任务自动路由，Companion 不得逐轮自动路由。

每段稳定关系锁定一份版本化 Voice Stack：

- Provider；
- Model revision；
- Companion Prompt Adapter；
- Voice Profile；
- Context policy；
- Self Canon revision。

普通界面只显示“极昼当前的声音：稳定”，具体模型、费用和上下文策略放入幕后。Voice Stack 元数据不随升级自动删除；只要原 Provider 和模型仍可访问，用户可以回退到先前接受的版本。

模型或 Prompt Adapter 不得静默替换。当前声音不可用时，系统明确提供等待恢复、临时试用备用模型、选择其他模型或只查看历史；不能偷偷让另一个模型生成角色回复。

切换前必须进入非 Canon“试演”，用当前与候选模型分别生成普通闲聊、共同经历召回、现实工作及权限边界表达，以及当前消息候选。试演不写记忆、不产生真实行动、不修改当前对话或历史。用户可以保持原样、从下一个场景正式切换，或只在当前分支试用。

正式切换保存当前关系与场景 checkpoint，固定新 Voice Stack，从下一个明确场景生效，保留回退入口，不重写历史。新模型继承可见 Canon，不继承旧模型不可见的内部状态。产品必须提示：“同一份记忆和关系会保留，但表达方式可能变化”，不能承诺任意模型都百分之百扮演成同一个角色。

### 7.11 有限生活感

用户离开时，极昼可以在叙事层整理旧日志、守着书房、修补灯火或阅读 Self Canon 中已有记录，使它不像被暂停的软件。

这些活动不能声称观察了用户未授权的现实活动、完成未经批准的工作、与用户发生新的共同经历，或在后台改变关系状态。有限生活感不产生现实副作用，也不生成需要用户为角色情绪负责的离开惩罚。

### 7.12 Roleplay 验收

下一版必须证明：

1. 极昼在第一次见面前已有稳定 Self Canon，但不伪造与用户的共同过去。
2. 用户不用填写复杂设置表即可完成称呼、关系起点和关系记忆许可。
3. 长对话始终保留 Identity Core，能正确区分 Self Canon、共同经历、场景和现实事实。
4. 用户可按需重新生成、切换已生成版本、记住一刻、通过预设或自由文字说明“这不像极昼”、进入幕后或创建分支。
5. 角色语境中的现实请求能平滑进入独立系统行动确认。
6. 工作运行时用户仍能与极昼交谈；工作返回时角色交还和真实结果同时成立。
7. Companion 模型不自动切换；候选模型先试演、正式接受后建立身份节点，并可在可用时回退。
8. 任何 Roleplay 操作都不能改变权限、真实文件改动、结果、计费或操作记录。

### 7.13 角色包与角色系统

极昼是随产品签名交付的默认角色包。用户可以把角色包当作高级主题导入，替换背景、配色、角色形象与行为表达；官方极昼只是默认预设，不再是写死的产品常量。

**角色包格式**（zip，schema 校验 + 资产尺寸限制）：

- `metadata.json`：包 id、名称、版本、作者、主题（配色/字体）、角色层字段（Canon、语气、台词模板、记忆范围）、资源清单、桥接 API 版本；
- `assets/`：背景图、角色贴图、动画循环、Live2D 模型；
- `skills/`：角色技能（文本），声明模型可调用的视觉工具。

**三层分离**：

1. 主题层：背景、配色、字体、氛围；
2. 角色层：身份、Canon、语气、台词模板、记忆范围；产品文案常量全部抽离进包；
3. 行为层：skills → 模型工具，实时切换背景、角色贴图、动画循环与表情预设；工具是纯展示层，不能接触文件、对话数据或系统事实。

**渲染与表达**：角色通过统一渲染接口呈现，adapter 支持贴图、动画循环与 Live2D。视觉状态以在场、聆听、思考、需要你、带回结果、出问题为每个包必须提供的基线；作者可在此基础上自由增加表情、背景与动画循环并为其命名，模型通过工具按名称调用。表达不做持续波形或闪烁装饰。

**记忆按角色隔离**：称呼、共同经历与关系记忆按角色命名空间存储；切换角色即开始新的关系，不串台；极昼预设包自带命名空间。
#### 角色包创作与作者体验

角色包创作以内容创作者为对象，不要求编程背景；官方极昼包随产品交付，作为完整范例与校验基准。

- 元数据由表单生成：填写名称、主题、Canon、状态素材等字段后自动产出 metadata.json，作者不接触 JSON 语法。
- zip 由打包工具导出：资产按约定目录摆放，"导出角色包"一键打包；导入在设置页或初始化完成。
- skills 提供填空模板：行为描述写作"当[事件]时调用[工具]切换[状态]"；官方极昼包即完整范例。
- 视觉状态以在场、聆听、思考、需要你、带回结果、出问题为必选基线；作者可自由增加额外表情、背景与动画循环并为其命名，模型通过工具按名称切换。
- schema 校验给出中文错误信息：导入时逐项提示"缺少 background.png"一类问题，不暴露技术细节。

**边界**：

- 同一时刻只有一位激活角色；不提供多角色列表、群聊或第一方角色市场。
- 角色包是内容格式，不是 Prompt 编辑器；Host 的事实、权限、证据、UI 与 worker 隔离不受角色包影响。
- 导入入口位于设置与首次初始化；可一键恢复极昼。
- 角色包当前不含脚本。脚本（沙箱 iframe/Worker + 白名单桥接 API，不暴露文件系统、网络、宿主 DOM 与用户数据）列为可选未来能力，不进入 P0/P1；格式预留 `scripts/` 目录与桥接 API 版本字段，后加不破坏既有包。

**阶段**：P1 完成格式规范与 schema、主题参数化、角色层文案抽离、设置与初始化导入入口；P2 完成渲染器抽象、模型视觉工具面与记忆按角色隔离。

**工程契约 · 平台与移动端（桌面框架）**：当前桌面工程支持 macOS/Windows/Linux；移动端后续独立设计与实现，只保留角色对话、历史、重新生成/版本切换、Relationship Canon 与用户批准的共同记忆；显式禁用本机文件/项目、worker/executor、Terminal、自动化、MemoryCore 本地 helper、桌面权限与系统集成，且不把桌面 UI 直接缩放到手机。

## 9. 能力承诺与格式门槛

产品只能宣传已经端到端验证的输入、操作和输出能力。当前文本、Markdown 或 CSV 能力不能被包装成完整的 Office 办公交付。

当极昼对外承诺现实工作场景时，必须先满足相应端到端能力门槛：

- 宣传“制作正式报告”前，真实支持 DOCX 与 PDF 的生成、预览和保存。
- 宣传“处理 Excel”前，真实支持 XLSX 的读取、分析、写入和预览。
- 宣传“制作 PPT”前，真实支持 PPTX 的生成、预览和保存。
- 宣传“整理文件”前，真实支持变更计划、执行记录、失败恢复，以及适用操作的撤销。
- 宣传“发送、预约或更新外部服务”前，真实支持对应连接器、逐动作授权、结果确认和失败状态。

若某项格式尚未达到门槛，界面只展示当前真实能力，不放置不可兑现的入口或示例。

## 10. 内部产品边界

面向普通用户不等于削弱底层边界。产品仍由 Host、内置 Pi Companion 和外部 worker 组成：

- Host 是唯一的状态、权限、证据、记忆和 UI 事实来源。
- 内置 Pi 是 Companion，不直接执行 shell、写入、联网副作用或取得凭据。
- Pi Worker、Codex 与 Hermes 都是外部 worker，只能处理用户确认的行动范围，不能取得 Companion 的关系记忆或改写产品 UI。
- 用户的批准、运行完成和结果采用是三个不同状态；熊或 worker 都不能代替用户作决定。

每个对话有独立历史、上下文、Scene State、当前对话约定、叙事分支和未完成事项；Self Canon 与同一 Companion Identity 贯穿所有对话，Relationship Canon 仅在用户明确启用后跨对话召回。后台工作不得打断前台；只有“需要你、做好了、没做成、目前无法确认”等关键事件产生一次通知。

Executor Console、steer、原始输出、Terminal 和用户接管继续存在，但归入“幕后”的单次工作高级详情。普通视图中的“补充要求、停下来、查看过程”分别映射到底层运行控制。Roleplay 的“重新生成、切换版本、继续、编辑、记住这一刻、这不像极昼、从这里另开一段”只能操作角色与关系内容，不能成为另一套运行控制入口。

长对话以可恢复 checkpoint 压缩，原始历史与证据仍由 Host 保存。叙事分支、场景摘要、上下文 checkpoint 和运行 checkpoint 是不同对象：前两者组织关系与叙事，后两者保证模型上下文及现实执行恢复。TencentDB MemoryCore 只作为随应用打包的本地语义记忆 helper，用于候选提炼和召回；Host Canon ledger 仍决定什么可写、可读、可删除，MemoryCore 不能成为产品事实来源，也不能暴露给 worker。

Companion Voice Stack 与 Worker 模型策略完全分离。Worker 可按任务自动路由；Companion 的 Provider、模型 revision、Prompt Adapter、Voice Profile、Context policy 和 Self Canon revision 必须固定、可见、版本化，不得在产品升级或故障回退时静默替换。

用户拥有完整的版本化 Custom System Prompt。`extend` 在默认极昼角色档案上叠加用户指令；`replace` 完全不注入默认角色档案。无论哪种模式，Host 的事实、权限、证据、UI 和 worker 隔离均不受 prompt 改写。普通用户通过“相处设定”调整角色与关系；完整原始编辑器属于幕后高级设置，不成为首次使用门槛。

参考 pi-setup 的目标是默认可用，而不是复制其 packages。默认能力由 Host 和产品代码实现；第三方包只可作为外部 Pi Worker 的显式、可见选择，不能进入 Companion。每项新工具、模型能力或市场包都必须先定义权限、普通用户操作面、证据和失败状态，不能靠 prompt 或角色叙事补齐。

**工程契约 · 诊断边界（桌面框架）**：诊断仅写入当前发行的 userData，本轮永不上报且 JSONL 只含 allowlist metadata，默认 30 天/总量 200 MiB；原始日志/trace 只属于“幕后/高级诊断”，不进入普通首页。Crashpad 默认本地开启，但 minidump 可能包含进程内存片段，未来导出必须独立明示并默认排除；netLog、contentTracing、Node diagnostic reports 与自动上报均未启用。

## 11. 交付顺序

1. 先用统一原型验证“已有自我的极昼—第一次见面—关系记忆许可—持续相处”的 Roleplay-first 入口。
2. 在同一原型中验证“角色语境提出工作—系统行动确认—后台处理—角色交还—结果预览—继续相处”的完整转换。
3. 完成 Self Canon、Relationship Canon、Scene State、Real Context、Identity Core、相处设定、叙事分支和关系修复的数据边界。
4. 完成 Host 的会话、权限、journal、证据、结果 artifact 和恢复能力，证明任何 Roleplay 操作不能改写 operational truth。
5. 实现版本化 Voice Stack、模型试演、显式迁移、不可静默切换和可用条件下的回退。
6. 接入 Pi、Codex 与 Hermes，验证普通界面不要求用户管理 executor；幕后仍能查看与接管。
7. 交付 P0 的材料理解、研究、真实文件操作和已声明格式能力；每项能力通过端到端结果验收。
8. 打包 MemoryCore，完成上下文恢复以及用户可管理的“熊记得的你”和“共同经历”，同时保持 Canon ledger 为唯一记忆决定源。
9. 提供版本化极昼角色档案、示例对话、三档沉浸、幕后通道和高级 Custom System Prompt。
10. 在核心关系与现实行动闭环稳定后接入连接器、例行事务、远程入口和 worker marketplace。
11. 在核心关系与现实行动闭环稳定后，按 P1（角色包格式与 schema、主题参数化、角色层文案抽离、设置与初始化导入入口）→ P2（渲染器抽象、模型视觉工具面、记忆按角色隔离）交付角色包系统。

完成标准不是“用户看得见 Agent 在运行”，也不是“熊偶尔说一句机魂不悦”。完成意味着用户愿意回到同一位有过去、有稳定身份的极昼身边；两者从真实的第一次见面开始形成可控、可持续的关系。用户能控制角色叙事、修复出戏和管理共同经历，也能让极昼安全地处理现实工作；角色表达、系统事实、权限、状态和结果始终清楚，且底层模型升级不会被伪装成身份没有变化。
