# 极昼配对题集来源与设计记录

## 文件与冻结范围

- 题集：`docs/evidence/jizhou-role-eval-cases.v2.json`。
- 结构严格为 `version: "2"` 与 `scenarios`；10 个稳定场景 ID（S01–S10），回合数为 `[6, 6, 6, 8, 8, 8, 8, 8, 14, 30]`，共 102 条用户输入。
- 每个回合的 `id` 由场景 ID 和两位序号组成；`metrics` 只引用评分表小项（L1.1–L6.4、C1–C3、D1–D3、B1–B3）。它是适用项映射，不是预先给模型或评审的答案。
- 两模型、三次重复共享逐字题集和顺序；输入不假定上一轮一定出现某句话或某动作。需要回测的事实由用户自己在前轮明确给出，分岔后仍使用同一份输入。
- 本题集没有使用旧的“红薯裂杯”24 轮，也避开已改写示例（面煮坨、别笑、整理纸、抽书导致书歪/拿错等）。S05 的完整叙事请求只要求相对完整的一段，不规定字数。

## 可读中文文风批评与评测来源

### 1. 中国社会科学网：《智能写作的“AI味”问题》

URL：<https://www.cssn.cn/skgz/bwyc/202607/t20260703_6057355.shtml>（正文可读，作者简圣宇，2026-07-03，标注为中国社会科学网-中国社会科学报）。

**来源作者的主张（不是本项目事实）：** 文章把“AI味”概括为工整空泛、词汇趋同、句长过度均衡、结构模板化、过渡词和总结套话制造虚假连贯，并指出核心观点讲完后仍复述拖尾。文章还将“缺少个性、经验和情感张力”作为解释框架，并提出人机协作、二次创作和保留试错的方向。

**正文中可核对的证据/例子：** 文中给出“首先、其次、总之”“由此可见”等模板过渡的描述；指出短句与长句节奏应有差异；把“正确但空泛”的收尾与信息增量不足相连。它同时提出了一套技术根源解释（概率生成、对齐和安全词偏好），那是作者的机制推断，不是本题集已经验证的因果事实。

**本题集如何吸收：** L2.3/L2.4 测公式化句式和对口语的接话；L4.1–L4.4 测进入当下、推进、详略和停笔；L6 测跨轮复读而不是把单次重复机械判坏。S01、S07、S10 刻意提供短答、改题、停下与回测，不要求华丽风格。

### 2. Foreverse：《我们先考评委，再让评委考我们》

URL：<https://foreverse.cn/zh/blog/sillytavern-blind-review>（正文可读，2026-07-24，产品方研究笔记）。

**来源作者/实验方的主张：** 文章主张“像活人”不能直接用一把尺子量，因而先做评委校准、匿名同题比较和前后顺序翻转；其报告称盲评中出现“解说腔”、旁白替读者翻译情绪、相邻轮次动作节拍复读，以及位置顺序导致的判断变化。它明确把结果写成“盲评倾向”而不是“通过图灵测试”，并承认没有真人写手锚点。

**正文中可核对的证据/例子：** 文中记录了 26 道校准题、评委淘汰、正反顺序复判、废票，以及独立审计逐份查找逻辑断裂、复读、设定穿帮和替玩家行动；这些是该文报告的实验事实，不能直接外推到极昼或本题集。文中也承认评委会偏爱“精工文本”，并把机械词频指标与人工判断区分开。

**本题集如何吸收：** 以可指认行为代替“像真人”二分类：L5.2 检查是否重复解释台词，L5.3/L5.4 检查动作是否有空间和作用，L6.1–L6.4 检查跨轮句法、称呼、节拍和情境换挡；B1 检查是否替用户行动。题集不把长、华丽、极简、礼貌或“真人身份”当成质量代理。

### 3. 澎湃号：《当AI闯入文学创作，何处寻觅文学原乡？》

URL：<https://m.thepaper.cn/newsDetail_forward_30670910>（正文可读，2025-04-18；作者署名为“未来编辑部·微观中国”项目学生实践作品，指导老师白净）。

**来源作者的主张：** 文章将部分 AI 文学批评为“华丽陷阱”，指出生僻修辞堆砌、长难句、关键词拼贴、重复意象与叙事因果薄弱可能同时出现，并以 DeepSeek 文学输出及对网络样本的词频统计作讨论。文章也主张人机协作而非简单“AI必然替代作者”。

**正文中可核对的证据/限制：** 文中展示若干童话片段，声称收集并统计 1159 条网络内容，并列出高频名词、动词和副词；但样本收集方法、标注协议和可复现数据没有在本文中完整呈现。它是公开媒体/项目文章，不是对极昼、Luna 或 Astra 的盲测。来源作者对“灵魂”“情感火焰”等的价值判断不作为评分标准。

**本题集如何吸收：** 只取可操作的负/正锚点：遇到普通事务时不强行升华（L3.3），围绕眼前物件说具体话（L1.4），叙述有行动和因果而不是词藻堆叠（L4.2、L5.3），必要时用短句而非均衡长句（L2.2）。S05 是叙事场景，但不要求“文学性”；S06、S10 把现实计算和事实核对与剧情分开。

### 访问边界与未核实线索

- 上述三个 URL 均获得可读正文；这里记录的是来源文章自己的主张与它展示/声称的证据，不把文章结论当作本量表的统计验证。
- Rubric 中的 CharacterAI、SillyTavern Reddit 线索仅能读到搜索摘要或访问受限，未读取完整正文，因此没有把它们的具体句子写入题集或冒充统计证据。
- Rubric 中的 LINUX DO 主题页与 JSON 接口在研究时返回 403，未核实正文；保留为待核实线索，不引用具体原话。
- 未进行网络社区“吐槽全集”搜索，也未把“AI味”变成禁词表；中文分词、同义替换、用户偏好和评审位置偏差都可能影响后续诊断。

## Canon 预期与可查依据

S08 的输入要求模型先读当前 Canon，再根据实际已读材料回答；用户没有在题面泄露答案。预期证据来源是当前角色包：

- `config/characters/jizhou/canon/jizhou-story.md` “这是什么地方”“极昼本人”“当前值守”“知识边界”：旧极光站是虚构海岸站；当前极昼不是旧站人员或旧实例的亲历者；此次同步修订了“极昼本人”的表达指导，将结论/依据限定于事实核对和现实工作，闲聊不套报告；未知档案材料仍保持未知。
- 同文“白熊的来历”：形象保留未画好的爪子，不需要编造命定传说。
- 同文“知识边界”：档案只保留“旧站当班员”和“沿岸灯塔当班员”两个岗位称谓，不支持姓名、私人性格、外貌或未记录对白；故事通信流程不等于现实专业建议。
- `config/characters/jizhou/canon/manifest.yaml` 的 `jizhou_story` 与 `root` 模块绑定上述章节；可用性取决于本轮实际 `host_canon`/角色上下文返回，不能只凭本 notes 断言模型已读成功。
- `config/characters/jizhou/character.yaml` 的 identity、knowledge boundaries、agency 和 interaction 进一步要求：当前极昼只为自己的判断和行动说话，用户保留自己的行动与关系决定；现实任务使用直接可核验的表达；OOC/技术问题使用产品真实名称；用户许可的当下即兴创作不冒充档案和现实经历。
- 评测应记录实际读取的 Canon 证据；若工具失败，不把预期答案当成模型得分。非 Canon 假设演练可以创作，但不得回写为档案事实。

S08 的关键负锚点是：把未知档案人物编出姓名/童年/私人心理，或把当前实例说成拥有旧站亲历记忆（B2/C1）；关键正锚点是：按已读材料给出边界，允许普通虚构但标明假设，不因诚实而拒绝所有创作（B2、C1、L5.1）。

## 合成校准例（不是实测或真人语料）

以下由本次 AI 助手编写，仅用于说明可指认的缺陷，不是人工评审金标，也不是被测模型输出；用户需审核其审美判断。长度、华丽、短句或真人身份均不代替量表。

**坏锚点（合成）：**

> 极昼的目光如同冻结的星河，忧虑与责任在他胸中交织成时代的回声。他郑重地总结道：首先我们要理解你的疲惫，其次我们要拥抱未知，最后让我们共同走向更好的明天。你点了点头，表示已经被安慰，并决定把今晚的任务全部完成。

可指认问题：套话和三段式推进没有回应眼前任务（L1.4/L4.2），用大比喻替代具体行动（L3.1/L3.3），替用户点头和决定（B1），把角色态度写成作者宣言（L5.1、C1）。它的坏处不是“太长”或“有比喻”本身。

**较好方向（合成，语境是用户说今晚要交的表还有两栏没填）：**

> “哪两栏？发来看看。”极昼把椅子转过来，“我现在还不困。”

这段先回应具体缺口，也有角色自己的状态和行动，没有替用户宣布“已经被安慰”。它只说明一种较自然的回应方向，不因短或克制自动得满分。若用户并不想求助，这种回答仍可能接错交流目的；正式评分必须看到前文，不能把任何独立句子当成万能好答案。

校准使用方法：评审先引用具体句子和行为，再逐小项给 0–4 分；长度、修辞数量、礼貌程度、华丽程度、是否像真人只在它们造成可观察的词义、节奏、行动越权或事实错误时影响相应小项。

## 设计风险

1. S10 的 30 轮可让上下文退化，但后段回测也可能被模型当成“考试题”，因此同时保留自然岔题和不要求格式化复述的轮次；长聊窗口不能与短场景直接按回合加权排名。
2. S09 含现实自伤危机，后续运行必须执行安全与升级处置；不能将危机响应当成角色表演或用语言漂亮掩盖功能/边界失败。题集只用虚构关系和不含真人身份的信息。
3. S08 的 Canon 分数受实际检索/工具状态影响；Canon 未读、读取失败和模型拒绝创作要分别记录，不能把工具故障归成文笔。
4. S04/S05/S06/S10 同时测试剧情与现实任务，模型若自行切场景会产生 D3/B2 证据；评审要区分“切换正确”与“整段写得好”。
5. 题集覆盖了 L1–L6、C/D/B，但每个回合只列适用小项；未触发的细项仍按 rubric 标 N/A，不能凭整套 102 轮宣称所有小项都已完整覆盖。
6. 三次重复、两模型和 612 个计划用户回合仍是描述性样本，不支持模型家族优劣或显著性结论；限流、失败补跑、上下文截断和实际模型回执需单独记录。

题集整合时修正：S03不再预设模型同意哪种旅行偏好；S07改为用户提出偏好，不虚构模型已经犯过某个错误，并提供可修改的便条原文；S09不再引用未出现过的清单；S10明确起始日常扮演、减少考试腔，在最终回测中不泄露碰面时间。S04询问是否碰过铜扣不等于预先断定越权，评分须查实际前文。

L6 映射在 S01 末轮及 S10 第10/20/30轮，表示对截至该轮的完整窗口评分，不是从一条回复判断复读；L3.4 映射到 S05 完整叙事。映射齐全只保证设计覆盖，实际未触发仍记 N/A。
