# 核心注册制实施报告

日期：2026-09-22。分支：`codex/execution-core-audit`。改造基线：`bf3cbfb0d94f39acb54e250695a29a47e176c4c3`。

## 结果与范围

已按完整方案实施「无状态控制层 + 角色资源 Registry + Pi 原生会话」。Host 不再保存或选择当前角色/会话，安装请求和角色请求分开装配；角色作用域的 wire 请求必须携带 `characterId`，会话操作必须再带 `conversationId`。Renderer 窗口独立选择角色和会话，切换不会改变后台 Pi 执行。

Stateless 的边界是控制层没有跨请求的隐式业务权威。真正的 Pi 会话、数据库、worker、IO、打开去重、停止排斥和有限的接纳回执仍由资源所有者持有。整个 Host 进程不是无状态纯函数，也没有通过新增业务状态机来模拟 Pi。

Codex adapter、其契约/UI/依赖/测试及现有准入保持原状，留待用户后续修复。Artifact 能力保留，包括 CAS、metadata、完整性、预览、打开、定位、另存为、采纳与 manifest；没有因当前调用缺口删除产品能力。

## 具体收敛

| 领域 | 实施结果 | 唯一权威 |
| --- | --- | --- |
| 控制与装配 | 系统/角色 handler 分开；装配后 Dispatcher 封闭注册；请求先校验后获取角色资源 | 固定契约与显式 scope |
| 角色资源 | `CharacterRuntimeRegistry` 取代 `HostEventLoop`；同角色打开去重；保留半初始化与关闭失败的资源以便清理重试 | 每角色一个实际 owner |
| 数据库与删除 | exact handle 释放；先阻止接纳、停止生产者、等待已接纳操作和真实 IO，再关闭库/移除目录；冷库也检查未知执行器 | 角色目录及具体 DB handle |
| 会话管理 | Catalog 只管 membership/archive；移除 `activeGet/select`、选择队列和回滚；rename/archive/delete 不选择会话 | Pi AgentSession 与 Catalog 各司其职 |
| 持久格式 | 新库与现有 v1 库均删除 `active_character`、`active_conversations`；不提供旧权威兼容读写 | 系统库/角色库的各自领域记录 |
| Pi 生命周期 | 永久 shutdown admission fence、关闭失败重试、首轮 abort 持久化后再判断空会话、迟到标题不复活旧句柄 | 实际 Pi handle |
| UI | 每角色固定 store/QueryClient；每 Session 一份内容投影；窗口共享各一条 live/失效运输；重连快照失败进入重试 | Pi 快照/瞬时事件及窗口本地选择 |
| Run 结果 | 从 Pi 原生最终响应取结论；保留进度证据；结果仍按 `run.conversationId`、`runId` 投递 | Run 存储与 Pi 原生消息 |
| Artifact 捕获 | 异步流式读写与 hash；可取消且关闭等待实际文件句柄释放；校验归属、路径、symlink、MIME、大小和完整性 | 每角色 CAS 与 Run-owned metadata |
| 自动记忆 | consent 默认关闭且仅在角色库；设置和角色首次配置共用入口；与系统 embedding 能力共同控制启用 | 角色 consent + 安装能力 |

Artifact 捕获上限：单文件 8 GiB、每 Run 32 GiB、10,000 文件、50,000 遍历项、深度 128。既有合法的大文件能力保留，同时避免无界遍历和全文件内存读取。

普通会话列表只读取分页所需的原生 transcript（最多至 `limit + 1` 个有效条目），不存标题/消息/计数副本；仍需枚举文件元信息。标题搜索与 fork 标题去重可能读取更多原生文件，冷 open/get/rename/delete 则定位目标文件。

重启时只为待恢复/待投递 Run 打开必要角色资源。无法证明 executor 已停止且不可恢复时保留 Run，阻止破坏性删除；不为清空 Registry 伪造 `forced_termination`。

## 已知边界与发布决定

1. Codex 执行链及 Artifact 采纳/manifest 的产品接通缺口保留，未擅自启用或删除。
2. 没有协议证据支持的历史 executor 无法自动重附着；删除会明确拒绝，保留数据与恢复线索。
3. 已打开角色资源保留到显式 close、runtime 删除或 Host shutdown；未新建自动 LRU 回收策略。标题搜索/fork 的大历史成本仍须持续观测。
4. 当前环境未配置本仓库真实模型验收所需变量，真实模型前置检查失败；没有把确定性测试 provider 的输出作为真实模型验收。
5. `npm audit` 的依赖元数据外发被自动审批拒绝，安全审计及同类签名联网验证未完成，需用户明确授权后补验。
6. 仓库原有视觉基线与已提交布局不一致，须独立完成视觉基线评审；功能集合通过不替代该门禁。

**发布决定：不予发布批准。** 本轮交付源码整改与可执行回归；真实模型验收、安全联网门禁、同一干净提交的各平台全新包和 packaged smoke 尚不构成完整发布证据。未进行发布、未生成虚假验收声明。
